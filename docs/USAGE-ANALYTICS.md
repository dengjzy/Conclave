# 用量账本与额度自动化

总览 → 统计用本机账本展示最近 7／30／90 天的消耗：顶部的 token 合计、金额和缓存命中，「近 N 天用量」逐日的 token 与金额，「token 构成」「按 Agent」两个环，以及「按模型」「按账号」两张表。工具栏的来源切换（全部／Conclave／外部）和下钻对这些卡片一起生效：点环里的 Agent、表里的模型或账号只看它，下钻后「按模型」下可展开最近 100 个会话，「返回全部」清除。工具栏的刷新同时重新扫描日志。对话回合、任务运行、验收率、失败中断和「Conclave 里的工作」仍只描述 Conclave 内的工作，不随来源切换。缓存命中是缓存读取占输入的比例：各 Agent 记下的输入已含缓存读写。

## 数据与进程边界

core 的 `UsageAnalytics` 管理 SQLite 账本；desktop 通过 `usage.history`、`usage.scan`、`usage.forecasts` 读取，不访问本地凭据或 transcript。协议用 `usage-analytics` feature 控制入口，新增字段和方法不改变旧统计接口。账本只保存消耗、来源、模型、时间、目录和账号身份快照，不保存正文或访问令牌。

首次启动回填现存历史，之后每分钟检查变动。Claude、Codex 的目录来自 adapter 的 `usageTranscripts` 和账号目录；默认目录解析与会话导入共用，按真实文件路径去重。用量不能使用 `SessionImports.list` 的结果：导入列表有意排除了 Conclave、自建子会话及临时目录，而这些都可能发生消耗。

JSONL 和 OpenCode 的读取运行在 `usage-scan-worker` 中；源码启动用 tsx 加载，桌面打包提供独立的 worker bundle。JSONL 检查点保存文件身份、已解析字节数、头部和边界摘要、解析基线。只提交完整行；文件截断、替换或前缀变化时重建。单行上限 32 MiB，损坏行跳过。Codex 压缩历史整体解压重读，通过事件身份与未压缩副本去重。OpenCode 同时检查数据库及 WAL 的变动，以只读方式解析 v2／旧版消息；迁移后的同一会话、消息只计一次。

Cursor 的本地聊天文件没有 token。core 使用 CLI 已有登录，只读请求其用量明细接口：最多 40 页、每页 300 条，成功结果缓存五分钟。认证、分页或网络失败保留旧记录，界面提示来源不可读。其历史覆盖服务方仍提供的最近 92 天，不代表能恢复服务方已清除的历史。

每个来源独立失败；扫描完成通知 `usage.analyticsChanged`。扫描进度与用量记录持久化，重启不重复累计。Conclave 已结束阶段的用量、标题和翻译等小请求也会回填；新增小请求和预热在完成时直接入账。

## 去重、来源与身份

账号键是 `(agent, account)`，因为每种 Agent 的本机账号都叫 `default`。多个 Claude、Codex 账号共享历史目录；目录、文件名和当前账号都不能证明历史属于谁。同一原生 session 可以在多个账号上继续。

原生请求通过消息／请求身份去重；Claude 的同一请求流式更新保留最终快照，Codex 的累计基线不作为每次请求重复相加，分叉复制的历史使用相同事件身份。Conclave 的 live 回合是原生日志尚未落盘时的回退：按 session 和回合时间范围比较覆盖，选择原生事件或 live 汇总，不能将两者相加。原生事件不足以覆盖完成回合时保留 live 汇总。

账号和 Conclave 来源由消费发生时的阶段确认，记录阶段身份快照；此前的外部消耗保持外部，不因后来导入而改变。无法确认账号的历史归为「未知账号」。删除账号、改标签或重新登录不改写已记用量。走模型服务商的阶段不记到官方订阅账号，也不套官方价格。

OpenCode 只有会话累计值而无消息明细时，作为未分配的会话累计显示；它不能被当成最后一天的一次请求，也不参与所选范围的总量、模型分布和每日趋势。美元分开显示服务方报告与按 API 标价折算，缺少价格或缓存信息时保留 token、金额未知；金额合计同时展示计价覆盖率，不代表订阅实际扣款。

## 额度预测

`usage_quota_samples` 按 Agent、账号、身份、窗口种类和模型隔离。身份变化、百分比回退或重置时间变化时清除旧基线。最近一小时有至少三次读数、跨度至少十五分钟时，按百分比增长计算速率；近期没有增长不提供耗尽倒计时。样本不足时使用窗口平均速度并标注依据；超过三十分钟或读取失败的数据标为过时。

新额度读数的可选 `recentRate` 同时供 `windowPace` 使用，因此额度卡片、建议和 Agent 排序使用同一近期速度；旧 core 或读数不足时保留原有窗口平均算法。预测只使用服务方额度百分比，不把 token 或金额换成订阅额度。状态栏的额度卡片只在某个窗口预计在重置前用完时，在该窗口下加一行「按目前速度，约 X 用完」，悬停可看依据；不会用完的不另外说明，完整的预测列表在用量分析里。

## 按账号自动化

设置 → 用量额度通过 `usage.automation`、`usage.configureAutomation` 配置 `UsageAutomation`，所有主动操作默认关闭。只支持 descriptor 声明了 `quotaAutomation` 的 Agent；当前为 Claude 和 Codex。配置绑定保存时识别的账号身份，身份不明或变化时暂停，需要重新登录并保存。账号移除后不再执行其配置。

每天可配置多个 HH:mm 时点，按保存的 IANA 时区执行；休眠后迟到一小时内补跑，更晚跳过。窗口重置后的预热可以单独开启，也可以与每日时点组合；会覆盖下一个每日起点的窗口等待该起点。一次请求同时启动所有闲置窗口，不为每个窗口重复发送。成功或结果不明的请求有冷却期，避免服务方为闲置窗口不断移动重置时间时重复预热。

预热使用 descriptor 的轻量模型，在独立临时目录发送最小请求，无用户 MCP、项目或知识库。账号通过 `AgentAccountStore.launch(agent, account)` 显式固定，不修改全局当前账号；CLI 由 daemon 的 pipe session 托管，三十秒超时后停止。每日／窗口触发及结果持久化，明确失败指数退避，每个触发最多三次；core 崩溃时已发出但结果不明的预热不重发。仅在 core 运行时执行，不新增系统后台服务。

Codex 有两个独立用卡开关：

- 周额度耗尽：只有已有调度工作等待额度时才检查，先沿用 `switchFrom` 尝试换号，尊重用户的自动换号开关；没有可用替代且目标账号仍确认为周额度耗尽时，使用最早到期卡。成功后直到用卡前的原周窗口结束，不再因周耗尽自动用卡。
- 临期：最早到期卡剩余不超过 24 小时，且能清除的有效窗口已有消耗时使用。不为制造消耗额外发送请求。缺少明确卡 ID、凭据不可用或状态不明时不创建新的消费。

手动用卡、周耗尽、临期和设置中的重试共用账号锁。发请求之前持久化目标账号、身份、卡 ID 和服务方幂等请求 ID。超时留下 pending，后续继续使用原请求；不能改账号或卡，也不能让另一个操作越过未确认结果。自动重试最多三次，仍不明时设置提供「核实并重试上次用卡」。用卡后沿用 `UsageService.useResetCredit` 刷新目标账号，随后通知已有调度器重新检查额度等待，不另建续跑队列。

## 验证

解析、worker、对账、账号归属、预测和自动化均使用隔离目录、模拟服务与可控时钟测试，不调用真实模型或消费真实重置卡。修改时运行 `pnpm typecheck && pnpm test`；界面修改另运行 `pnpm build`，打包 worker 通过 `pnpm --filter @conclave/desktop bundle:backend` 检查。
